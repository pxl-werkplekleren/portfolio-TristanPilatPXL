WPL2 Case: Pop & Clay

Gesimuleerde stage · HTML / CSS / JS · C# ASP.NET Core 4-lagen · Vue.js · SQL Server · 8 studenten

01. Beschrijving van de case

Pop & Clay is een lokaal bedrijf dat workshops en handgemaakte producten rond kleiboetseren aanbiedt. De eigenaresse regelde alles via Instagram: geen eigen website, geen productcatalogus, geen manier om bestellingen of klanten bij te houden. Dat werkte ooit, maar niet meer. Onze taak was om daar verandering in te brengen.

Het team en de rolverdeling

WPL2 was een gesimuleerde stage waarbij acht studenten uit drie richtingen samenwerkten als één team met een echte opdrachtgever. De drie studenten Digitale Vormgeving namen het UX-traject voor hun rekening: benchmarks, doelgroepanalyse, wireframes en de volledige visuele huisstijl. Zij bepaalden hoe de applicatie er moest uitzien en aanvoelen. De webstudent bouwde de publieke webshop op basis van dat ontwerp in Vue.js. Wij als programmeurs waren verantwoordelijk voor alles erachter: de backend, de database en het admin dashboard.

Wat er gebouwd werd

De backend is een ASP.NET Core Web API in C#, opgebouwd in vier lagen: Domain, Application, Infrastructure en WebAPI. Die opdeling zorgt ervoor dat elke laag zijn eigen verantwoordelijkheid heeft en niet door de andere loopt. Authenticatie verloopt via JWT-tokens, wachtwoorden worden gehasht met bcrypt en de toegangscontrole is role-based: admin, medewerker en klant hebben elk andere rechten. De API documenteert zichzelf via Swagger.

Het admin dashboard is gebouwd in HTML, CSS en vanilla JavaScript, zonder frontend-framework. De schermen, formulieren en communicatie met de API zijn zelfgeschreven, maar voor specifieke functionaliteit hebben we bewust externe packages en diensten gebruikt: Stripe voor betalingsverwerking, Mailtrap voor e-mailverzendingen en Flowise voor de AI-chatbot. AI werd ook ingezet als werktool tijdens de ontwikkeling. Het dashboard bevat modules voor gebruikersbeheer, medewerkersbeheer, productbeheer, bestellingen en een loginlogboek. De database draait op SQL Server.

02. Mijn aandeel

Mijn werk reikte van de database tot de frontend, dwars door de hele stack.

Admin dashboard: HTML, CSS en JavaScript

In het admin dashboard bouwde ik de schermen voor bestellingenbeheer en gebruikersbeheer. Zonder framework schrijf je alles zelf, en dat merk je: elke tabel, elk formulier, elke validatie en elke foutmelding moest ik zelf opbouwen. Data laadde ik op via de Fetch API, communicatie met de backend verliep via authenticated requests met een JWT-token in de header. De loginflow, het bijhouden van de sessie in session storage en het doorsturen naar het juiste scherm op basis van de gebruikersrol, waren onderdelen waar ik ook foutopsporing op deed tussen de JavaScript-kant en de backend.

Backend: C# ASP.NET Core

Voor de modules die ik in het dashboard had gebouwd, schreef ik ook de bijbehorende backend. Dat betekende controller-klassen, repository-implementaties en de koppeling daartussen via dependency injection, allemaal binnen de vierlagenstructuur die we als team hadden vastgelegd. Die structuur was in het begin even wennen, maar het hield de code overzichtelijk naarmate het project groeide.

Database en testen

Voor de database droeg ik bij aan het schema en de bijhorende queries. Ik testte de endpoints via Swagger voor de frontend erop werd aangesloten. Dat was een goede gewoonte: kleine problemen werden zichtbaar voor ze echte integratieproblemen werden.

Wat ik meeneem

Iets wat me is bijgebleven: afstemming is net zo waardevol als code schrijven. Ik stelde vroeg in het project mee voor om samen de datamodellen en API-structuur vast te leggen voor we afzonderlijk aan de slag gingen. Dat heeft achteraf concrete problemen vermeden. In een team van acht mensen uit drie richtingen merk je snel dat een duidelijke gedeelde afspraak meer waard is dan individueel snel werken.

03. Wat ik leerde

🤝 Full-stack teamwerk

In een team van acht met drie disciplines leer je dat goede afspraken over API-contracts en component-grenzen essentieel zijn. We definieerden vroeg in het project samen de datamodellen en API-endpoints, wat later refactoring-werk voorkwam. Ik leerde ook communiceren met design-studenten over technische haalbaarheid van hun mockups.

Vanilla JavaScript in een echte applicatie

Het bouwen van een volledig admin dashboard zonder framework dwingt je om alles bewust te structureren. Ik leerde de Fetch API correct te gebruiken voor beveiligde requests met een Authorization-header, API-responses netjes te verwerken inclusief foutstatussen, en de gebruikersinterface te updaten zonder een framework dat dat voor je doet. Dat geeft inzicht in wat frameworks eigenlijk oplossen.

SQL Server en repository pattern

Door de databaselogica volledig te scheiden van de controller via het repository pattern, blijft elke laag leesbaar en aanpasbaar zonder de rest te breken. Ik leerde hoe een goed ontworpen databaseschema met duidelijke relaties tussen tabellen de backend eenvoudiger maakt, en hoe een kleine fout in een tabelstructuur of kolomnaam uren debuggen kan kosten.

🔄 Wat ik anders zou doen

Ik zou vroeger pleiten voor een gezamenlijke backlog of taakbord. In de beginfase waren taken niet scherp genoeg verdeeld, wat leidde tot korte overlappingen tussen programmeurs. Een gedeelde sprint-planning aan het begin van elke week had dat eenvoudig voorkomen en ons tempo verhoogd.

04. Finaal resultaat

🚀 Het eindproduct

Het eindresultaat is een volledige webapplicatie voor Pop & Clay met drie afzonderlijke gebruikersomgevingen. Klanten kunnen het productaanbod bekijken, medewerkers en admins beheren het platform via een admin dashboard gebouwd in HTML, CSS en vanilla JavaScript. De backend is een ASP.NET Core Web API in C# met JWT-authenticatie, bcrypt en role-based access control. De database draait op SQL Server.
